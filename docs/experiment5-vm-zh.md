# 实验5：虚拟内存综合实验

## 1. 实验目的

本实验从一个直接可见的问题开始：在初始系统中运行

```sh
make download-files
make emulate
next model.bin tokenizer.bin 1 "hello"
```

`next` 会在真正生成第一个词元之前失败，常见输出是：

```text
malloc failed
```

这不是一个普通的用户态程序错误。它暴露的是一个操作系统问题：程序向内核申请了很大的虚拟地址空间，初始 xv6 却把“保留一段地址”立即理解成“马上分配全部物理页”。当模型权重、运行时缓冲区和 KV 缓存一起出现时，64 MiB 的模拟器内存很快就不够用。

本实验希望你按证据一步步改造 xv6 的虚拟内存系统，而不是直接背诵某个结论。完成后，你应该能够解释并实现：

1. 如何从内核向用户程序提供可信的内存观察数据。
2. 为什么虚拟地址空间可以先被保留，而物理内存可以等到第一次访问时再分配。
3. 如何把只读文件内容映射到虚拟地址，而不是先整块复制到匿名堆内存。
4. 为什么多个进程或多个映射可以共享同一份干净的文件页。
5. 为什么 `fork` 不必立即复制父进程的所有物理页。
6. 如何在不改变虚拟地址布局的情况下丢弃暂时不用的匿名页，并在之后按需重新获得页面。

LLM 推理程序在本实验中是工作负载，不是最终目的。它的作用是把虚拟内存中的抽象问题变成可观察的问题：加载失败、内存占用、首次访问、共享、复制和丢弃。

## 2. 实验内容

本实验由 6 个连续小实验组成。每个小实验都有一个独立的观察程序和一个对应的自动评分阶段：

| 阶段 | 主题 | 观察程序 | 评分命令 |
| --- | --- | --- | --- |
| Lab 0 | 解释第一次失败 | `memwhy` | `make grade STAGE=lab0` |
| Lab 1 | 按需分配匿名堆页 | `demandcheck` | `make grade STAGE=lab1` |
| Lab 2 | 文件内容按需映射 | `mapcheck` | `make grade STAGE=lab2` |
| Lab 3 | 共享干净文件页 | `sharecheck` | `make grade STAGE=lab3` |
| Lab 4 | 写时复制 `fork` | `cowcheck` | `make grade STAGE=lab4` |
| Lab 5 | 丢弃未使用的匿名页 | `discardcheck` | `make grade STAGE=lab5` |

你需要主要阅读和修改这些区域：

5. 运行对应 `make grade STAGE=labX`。
6. 再继续下一阶段。

## 3. 实验步骤

### Lab 0：解释第一次失败

先从工作负载开始：

```sh
make download-files
make emulate
next model.bin tokenizer.bin 1 "hello"
```

初始系统中，`next` 通常会输出 `malloc failed`。这个输出只说明用户态分配失败，但没有告诉你到底是虚拟地址不够、物理内存不够，还是内核路径提前做了太多工作。

本阶段的目标是增加一个最小的可信观察接口：

```c
int vmstat(struct vmstat *st);
```

你需要实现 `vmstat` 的系统调用路径，让用户程序能够得到：

```c
free_bytes
proc_size
page_size
```

其余字段可以暂时填 0。

建议修改路径：

```text
include/vm.h
include/syscall.h
user/include/user.h
scripts/gen_usys.sh
kernel/proc/syscall.c
kernel/proc/sysproc.c
```

实现时应使用 `copyout` 把结构体复制到用户地址，不要在内核中直接解引用用户指针。

完成后运行：

```sh
memwhy model.bin
make grade STAGE=lab0
```

你应该能看到当前进程的虚拟大小、系统剩余物理内存和页大小。用这些数据解释：为什么“申请很大的堆空间”会在立即物理分配系统中迅速变成“消耗大量物理内存”。

### Lab 1：保留堆地址，第一次访问时再分配页

Lab 0 给出了证据：`next` 的失败来自大块内存申请和立即物理分配的冲突。现在的问题是：

```text
能不能先承诺一段虚拟地址，但只在程序真正读写某一页时再分配物理页？
```

你需要修改正向 `sbrk` 的行为。增长堆时，只增加进程的虚拟大小 `p->sz`，不要立即为新区域分配全部物理页。

随后在用户态缺页路径中处理合法的堆访问：

```text
缺页地址低于 p->sz
缺页地址属于用户堆区域
该地址尚未映射
分配一个清零的物理页
以 PTE_R | PTE_W | PTE_U 权限映射
返回用户态重新执行触发缺页的指令
```

还要处理一个容易漏掉的路径：内核向用户地址复制数据时也可能遇到尚未分配的 lazy heap 页。例如：

```c
read(fd, lazy_buffer, 1);
```

如果 `lazy_buffer` 所在页还没有物理页，内核不能简单失败，而应该走同样的按需分配逻辑。

运行：

```sh
demandcheck
next model.bin tokenizer.bin 1 "hello"
make grade STAGE=lab1
```

如果实现正确，`next` 应该能越过最初的 `malloc failed`，至少开始执行一次真实推理。

注意：运行时中的 KV 缓存是一个大块预留区域。它应该在词元生成过程中逐步被写入，而不是在分配时被整块清零。如果某个辅助函数在分配时触碰了每一页，那么它会把实验重新变成立即物理分配。

### Lab 2：把模型字节映射到虚拟地址，而不是整块复制

按需堆分配解决了最早的内存分配失败。接下来观察模型加载：模型权重来自文件，而且大部分是只读数据。如果运行时把文件内容全部读入匿名堆，就会产生一份额外的物理副本。

本阶段的问题是：

```text
能不能让一段虚拟地址记住“我的内容来自这个文件的这个偏移”，并在第一次读取时再加载对应页？
```

你需要实现一个小型只读映射接口：

```c
char *filemap(int fd, uint64 len);
```

`filemap` 应该保留一段虚拟地址，并记录足够的元数据，用于之后处理缺页。它不应该在系统调用中立即复制全部文件内容。

缺页时：

```text
判断缺页地址是否落在某个文件映射区间
分配一个物理页
根据虚拟地址计算文件偏移
从文件读取对应内容到物理页
把该页以只读用户页映射
返回用户态重新执行触发缺页的加载指令
```

你需要在 `struct proc` 中保存一个小型 VMA 数组。VMA 至少要记录起始地址、长度、文件对象和文件内偏移。即使用户在 `filemap` 返回后关闭文件描述符，映射仍然应该可用，所以内核需要持有文件引用。

运行：

```sh
mapcheck
make grade STAGE=lab2
```

观察重点：`filemap` 之后，虚拟地址范围存在，但驻留页数量不应该立刻大幅增加。第一次读取映射地址后，才应该出现对应物理页成本。

### Lab 3：复用干净的文件页

Lab 2 中，每个文件映射可以按需从文件读入页面。但如果两个映射读取的是同一个文件的同一个页，它们的内容完全相同，而且都是只读干净页。

本阶段的问题是：

```text
第二个映射能不能安装自己的 PTE，但复用第一个映射已经读入的物理页？
```

你需要在内核中增加一个很小的干净文件页缓存。缓存键不应该是文件描述符编号，因为文件描述符只是进程局部的整数。更合理的键应基于底层 inode 身份和文件页偏移。

实现要求：

```text
第一次访问某个文件页时，从文件读入物理页并加入缓存
再次访问同一文件页时，复用缓存中的物理页
每个虚拟地址仍然有自己的 PTE
共享页必须保持只读
记录引用计数，最后一个映射释放后再释放物理页
```

运行：

```sh
sharecheck
make grade STAGE=lab3
```

观察重点：两个虚拟地址可以不同，但它们的 PTE 指向同一个物理页。第二次映射同一干净文件页时，物理内存增长应明显小于重新复制一页。

### Lab 4：让 fork 先共享，写入时再复制

当进程已经加载或触碰了较大的地址空间后，传统 xv6 的 `fork` 会复制每个 resident 用户页。对于很多分支执行场景，子进程只是读取大部分页面，只写少量页面。立即复制全部页面会浪费时间和内存。

本阶段的问题是：

```text
父子进程能不能在 fork 后先共享物理页，直到某一方真的写入时再复制？
```

你需要实现写时复制 `fork`。

基本规则：

```text
fork 时不要复制可写用户页的物理内容
父子 PTE 都指向同一个物理页
清除父子 PTE 的 PTE_W
用一个软件页表项标志位标记写时复制
增加物理页引用计数
当用户写入写时复制页时触发存储缺页异常
如果该物理页仍被共享，则复制出一个新页
当前进程改映射到私有新页并恢复写权限
如果引用计数已经为 1，可以直接恢复写权限
```

内核 `copyout` 也必须能处理写时复制目标页。否则某些系统调用向用户缓冲区写数据时会失败或错误修改共享页。

运行：

```sh
cowcheck
make grade STAGE=lab4
```

观察重点：`fork` 之后父子进程仍然能读到原内容；某一方写入后，另一方看到的内容不能被改变；`fork` 的即时物理内存成本应显著低于 eager copy。

### Lab 5：保留地址布局，丢弃暂时不用的匿名页

前面几个阶段已经让系统避免了许多不必要的物理内存成本：堆页可以第一次访问时再分配，文件页可以第一次读取时再加载，干净文件页可以共享，`fork` 可以写入时再复制。最后还剩一个常见问题：长时间运行的程序可能维护一个大的逻辑 arena。某些块已经空闲，但程序仍希望保留整体地址布局，因为其他结构可能保存了地址或偏移关系。直接 `sbrk(-n)` 会缩小堆顶，不能表达“中间这一段暂时不要物理页，但地址仍然有效”。

本阶段的问题是：

```text
用户程序能不能告诉内核：这段地址以后仍可能使用，但当前 resident 匿名页可以丢弃？
```

你需要实现：

```c
int pagediscard(void *addr, uint64 len);
```

对范围内的匿名堆页：

```text
验证地址范围属于当前进程堆
按页边界处理起止地址
跳过本来就没有映射的洞
解除 resident 页映射
释放对应物理页
不改变 p->sz
```

之后如果用户再次读写被丢弃的堆页，它应该像 Lab 1 的 lazy heap 一样重新缺页，并得到清零的新页。

运行：

```sh
discardcheck
make grade STAGE=lab5
```

观察重点：丢弃后驻留页数量下降，但虚拟大小保持不变。重新访问被丢弃区域后，驻留页数量再次上升，并且内容应按匿名页规则重新清零。

这是本实验的最后一步。完成后，你应该能把 `next` 的行为解释成一组虚拟内存策略：先保留地址、第一次访问时再分配、文件内容按需读入、干净文件页共享、`fork` 写入时再复制，以及由用户显式告诉内核哪些匿名页可以忘记。
